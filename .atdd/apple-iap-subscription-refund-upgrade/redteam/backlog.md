## 상세 내용

### REL-1 (ADR-002) RabbitMQ 클러스터 장애

**문제**: RabbitMQ 클러스터 전체 장애 시 큐에 있는 메시지가 유실될 수 있음

**완화 전략 (현재)**:
- Classic Queue 사용
- Apple Webhook 재시도에 의존 (최종 일관성)

**전환 조건**:
- 트래픽 300 TPS 도달
- RabbitMQ 장애 발생 빈도 월 1회 이상
- 메시지 유실 사고 발생

**전환 시 작업**:
1. Quorum Queue 설정 추가
2. 기존 큐 마이그레이션
3. 3노드 클러스터 구성 확인
4. 다중 AZ 분산 배치

---

### SCALE-1 (ADR-002) Kafka 전환

**문제**: 1,000 TPS 초과 시 RabbitMQ 한계 도달 가능

**전환 조건**:
- 500 TPS 도달 시 PoC 시작
- 1,000 TPS 도달 시 전환

**사전 요구사항**:
- Kafka 클러스터 구성 방안
- Consumer 그룹 설계
- 메시지 포맷 호환성

---

### PERF-1 / SCALE-1 (ADR-003) 낙관적 락 관련

**문제**: 높은 동시성에서 낙관적 락 충돌 빈발 가능

**모니터링 지표**:
- 충돌율 5% 초과 시 알림
- 재시도 횟수 평균 2회 초과 시 알림

**대응 방안**:
- 사용자별 직렬화 큐 적용
- 분산 락으로 전환 검토

## Backlog 관리 정책

1. **정기 검토**: 스프린트마다 Backlog 항목 검토
2. **우선순위 조정**: 비즈니스 상황에 따라 우선순위 변경
3. **이관**: 구현 단계에서 처리하거나 별도 이슈로 생성
4. **자동 임계값**: 모니터링 지표 도달 시 자동 알림
